# V4 thinking-model execution amendment

Recorded before the first v4 **235B test** call. The original v4 test lock remains `74de5a1614fb6ffa67201c691a18a8830cfacbeb24f92a0072836275f7f86298`. Its episodes, prompt, response schema, score, analysis rule, model revision, 2,048-token output cap, 1,536-token thinking allowance, temperature, top-p, top-k, and prompt-derived seeds are unchanged.

The original serial development runner completed one valid 235B development response in 137.135 seconds for 1,544 output tokens. Extrapolating 450 serial calls would exceed the user's $75 RunPod cap. The serial development run was stopped after that case. No 235B test call had occurred.

The implementation-only change is to submit groups of 16 independent prompts together to vLLM 0.10.2. Each prompt keeps its own sampling seed and parameters. The two-pass thinking and constrained final JSON action logic match the frozen serial runner. Batched scheduling can change exact sampled text due to inference implementation and is recorded as a protocol deviation. It does not change public input or scoring. The additive runner is `scripts/run_action_v4_batched.py`, SHA256 `a1d9845b712d9a7ae557730d9a7012f4cc3facbdf5f6664aa783662d34ef0ab0`. Its source was finalized before the 235B test and is preserved with this amendment. The original lock's source-hash list does not include this new file, so this separate digest is necessary for replay.

The 16-case batched development ledger has SHA256 `f817d1587b20ef23698331d7316c5f3b69dc361931bd46fb713a92b857760e39`. All 16 responses were valid and passed local independent prompt, alias, and Bayes-risk replay. The batch generated 24,707 tokens in 146.035 seconds; full process wall time including checkpoint loading was 681.813 seconds. At the same batch rate, 450 test cases would take approximately 4,107 generation seconds, plus about eight minutes to reload the checkpoint. This is a planning estimate, not a test result or guaranteed duration.

The complete locked 235B test will use batches of 16, a 6,000-second process wall limit, and no episode limit. It will write every prompt, raw generation, action, and score to a ledger. If the process cannot finish all 450 cases within the wall and spend gates, it will be reported incomplete. The RunPod cap remains $75 including storage; no local GPU is used. The 32B test results were already observed before this throughput amendment, but no model-result comparison motivated the batching change. The 235B better-than-random criterion registered in the original rationale is unchanged.
